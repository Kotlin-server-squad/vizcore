## Context for the implementer

Work in `frontend/`. Run `pnpm test --run` after every task.

**The two modules that disagree.** `src/lib/state-counts.ts` decides which
bucket a state belongs to, and `StateBar` colours the chips from it.
`src/lib/coroutine-state-colors.ts` decides what the tree and graph draw. They
were written at different times and they do not match:

| State | `state-counts` bucket → chip colour | `coroutine-state-colors` |
|---|---|---|
| `WAITING_FOR_CHILDREN` | running → `--primary` | `secondary` (purple) |
| `CANCELLED` | cancelled → `--warning` | `default` (grey) |

So clicking the amber **Cancelled** chip filters the canvas to coroutines the
canvas then draws grey. That is the defect, and it is visible in the app.

`src/styles/palette.ts` already encodes the intended answer — its own comments
read `warning: suspended / cancelled / potential leak` and
`created: created, not yet started` — and its docstring names a `stateColor()`
consumer **that was never built**. That missing accessor is C-2.

## Decisions this plan makes

**N-1 — `WAITING_FOR_CHILDREN` takes the running colour and keeps its own icon.**
The spec's C-1 warns that neutralising `secondary` flattens this state into the
same grey as `CREATED` and `CANCELLED` — a real loss of information. Sharing the
*running* colour is not that flattening: `state-counts` already counts it as
running because structurally the parent is still live work, and the state stays
distinguishable by its clock icon and its own animation. Same bucket, same
colour; different state, different glyph.

**N-2 — `CANCELLED` becomes amber, matching the bar and the palette.** Not a new
decision: the state bar has drawn it amber since plan 3, and `palette.ts`
already lists cancelled under `warning`. This makes the canvas agree.

**N-3 — `RunsOnCard` reads thread activity, not the timeline.** The timeline
projection is source-only by design (D-02) and carries no per-event
`threadName`/`dispatcherName`, so the card can never fill from it. `/threads`
has the data, `SessionWorkspace` already holds it as `panelThreadActivity`, and
it works in replay too because that path is a client-side projection.

**N-4 — C-1 stays open.** 79 `secondary` references across ~25 files remain, and
the spec is explicit that retiring the token is a per-call-site decision. This
plan retires the *one* call site the spec identified as carrying real meaning.
