## 2. The "Right now" overview (the one thing CSS cannot do)

It needs data the page already has and layout above the main view.

- **Data, via the slot's props:** `SessionBodyProps` gains an optional `overview?: { counts: StateCounts; coroutines: readonly CoroutineNode[]; activity: ReadonlyMap<string, ActivityLine> }`. `SessionWorkspace` passes the values it already computes (`stateCounts`, `panelCoroutines`, `activity`). Classic ignores it; nothing new is fetched or derived on the page. (Shared change: `looks/types.ts`, `SessionWorkspace.tsx`, two small edits.)
- **What C shows, pure functions in `c-bold/overview.ts`, tested:**
  - `rightNowLines(coroutines, activity)`: for every coroutine not in a terminal state with an activity line, `{ name, text, waiting }`, where an unnamed coroutine is "An unnamed coroutine", never its id; holders first, then waiters, page order within each (the sketch reads "order-4 holds the lock. order-5 waits for it."). `ROW_CAP` (6) shown, then "and N more".
  - `stateSegments(counts)`: the non-zero buckets in the state bar's order (active, waiting for children, suspended, completed, cancelled, failed), each with its token colour and the label used for the bar's text alternative.
- **Layout without breaking the dock's size rules:** the dock sizes itself from the body's content height (`ResizeObserver` `contentRect`, which excludes padding): `main + 12 px + dock`. An overview in the body's flow would take height from the main view's 320 px minimum. So C's body is `position: relative`, the overview is its **third child** (allowed: extra children after the main view and the dock), drawn `position: absolute` at the top, and the body gets `padding-top` equal to the overview's height (14 px of it is the gap). The `RightNow` component measures itself and the body (`ResizeObserver`) and sets `--c-overview-h` on the body; on unmount (switching to another look, or nothing left to show) it removes it, so Classic's body (the same element) is left untouched.
- **Short windows:** the body's own height does not depend on its padding (it fills the page), so the overview can check, without feedback, whether `body − overview ≥ 320 + 12 + 120` (the main view's minimum, the gap, the smallest dock). If not, it steps aside (`visibility: hidden`, padding 0) instead of squeezing them, and comes back when the window grows.
- **Reading order:** the overview comes after the dock in the DOM. It holds no focusable element, so keyboard order is unchanged; it is a labelled `section` with an `h2`, so a screen reader can jump to it. Noted as a gap.
- **Hooks:** the `RightNow` component owns its hooks; C's `SessionBody` stays a render function with no hooks (called in place inside `SessionWorkspace`).

## 3. Gaps (the page shows things the sketch does not, or the other way round)

- **Node cards are outlined, not filled** with the state colour: graph state colours are shared across looks. The boldness comes from type, a 3 px outline and hiding the id rows.
- The **root** is a card like the others, not a purple pill.
- **"Right now" lists one line per coroutine** ("order-5 waits for inventory-lock · 1st"), not merged sentences ("order-5 and order-6 wait for it"): the page has the lines, not the facts behind them, and C does not re-derive them. Shown also during replay, where it describes the replay's moment.
- The **Replay button stays outlined**: only the Tree sketch fills it; C's Timeline, Problems and Story sketches outline every header button, and a filled Replay would need another hook.
- The page's **navbar**, the **main view's box and toolbar** (Graph/List, heading, state chips, Maximise), **Export** and **Run** are not in the sketch; they stay, restyled.
- The sketch's **Problems** tab does not exist yet (Part 7); the Inspector keeps its own content (no big-number summary).
- The activity text is the page's shared line (S-6): where a resource has no recorded name it already falls back to the resource's id on every look's cards; C shows the same line and does not re-derive it.
- The overview's **reading order** follows the DOM: after the dock (the slot keeps the main view and dock first). It holds no control, so keyboard order is unchanged, and it is a labelled region with a heading; its facts are a summary of the graph and the state chips.
- The banner and bar are not in C's Timeline, Problems and Story sketches; when those parts land, C can hide them there (they live in C's slot).

## The first view: dock start and card size (approved trade-off, built)

- **Shared, minimal:** `LookCard` gains an optional `dockShare` (the dock's starting share of the window), next to `fitMinZoom`. `initialDockHeight(windowHeight, share = DOCK_SHARE)` uses it; `useDockLayout(startShare)` reads it; `SessionWorkspace` passes `useLookCard().dockShare`. Without the field the dock starts at 40 % as before. A size the user gave the dock (resized now, or remembered) still wins.
- `useDockLayout` now keeps only the user's own size (`userHeight`). Without one, the dock follows the look's start, also when the look changes while the page is open. Only a resize stores a size; folding stores `height: null`, so one look's start never becomes another's. (Before, folding also stored the 40 % default; now a later visit computes 40 % of its own window.)
- **C:** `dockShare: 0.17` (153 px at 900 px tall), cards 180 × 104 (`fitMinZoom: 1`). The second line is clamped to one row, with the full text in its tooltip and in "Right now". The state pill is 13 px on one line ("Waiting for children" is 125 px in the card's 146 px). The box stays open.
