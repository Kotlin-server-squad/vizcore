## 2. The "Right now" overview (the one thing CSS cannot do)

It needs data the page already has and layout above the main view.

- **Data, via the slot's props:** `SessionBodyProps` gains an optional `overview?: { counts: StateCounts; coroutines: readonly CoroutineNode[]; activity: ReadonlyMap<string, ActivityLine> }`. `SessionWorkspace` passes the values it already computes (`stateCounts`, `panelCoroutines`, `activity`). Classic ignores it; nothing new is fetched or derived on the page. (Shared change: `looks/types.ts`, `SessionWorkspace.tsx`, two small edits.)
- **What C shows, pure functions in `c-bold/overview.ts`, tested:**
  - `rightNowLines(coroutines, activity)`: for every coroutine not in a terminal state with an activity line, `{ name: label || id, text, waiting }`; holders first, then waiters, page order within each (the sketch reads "order-4 holds the lock. order-5 waits for it."). `ROW_CAP` (6) shown, then "and N more".
  - `stateSegments(counts)`: the non-zero buckets in the state bar's order (active, waiting for children, suspended, completed, cancelled, failed), each with its token colour and the label used for the bar's text alternative.
- **Layout without breaking the dock's size rules:** the dock sizes itself from the body's content height (`ResizeObserver` `contentRect`, which excludes padding): `main + 12 px + dock`. An overview in the body's flow would take height from the main view's 320 px minimum. So C's body is `position: relative`, the overview is its **third child** (allowed: extra children after the main view and the dock), drawn `position: absolute` at the top, and the body gets `padding-top` equal to the overview's height plus 14 px. The `RightNow` component measures itself (`ResizeObserver`) and sets `--c-overview-h` on its parent; on unmount (switching to another look) it removes it, so Classic's body (the same element) is left untouched. With no overview content the variable is 0 and the body has no padding.
- **Reading order:** the overview comes after the dock in the DOM. It holds no focusable element, so keyboard order is unchanged; it is a labelled `section` with an `h2`, so a screen reader can jump to it. Noted as a gap.
- **Hooks:** the `RightNow` component owns its hooks; C's `SessionBody` stays a render function with no hooks (called in place inside `SessionWorkspace`).

## 3. Gaps (the page shows things the sketch does not, or the other way round)

- **Node cards are outlined, not filled** with the state colour: graph state colours are shared across looks. The boldness comes from type, a 3 px outline and hiding the id rows.
- The **root** is a card like the others, not a purple pill.
- **"Right now" lists one line per coroutine** ("order-5 waits for inventory-lock · 1st"), not merged sentences ("order-5 and order-6 wait for it"): the page has the lines, not the facts behind them, and C does not re-derive them. Shown also during replay, where it describes the replay's moment.
- The **Replay button stays outlined**: only the Tree sketch fills it; C's Timeline, Problems and Story sketches outline every header button, and a filled Replay would need another hook.
- The page's **navbar**, the **main view's box and toolbar** (Graph/List, heading, state chips, Maximise), **Export** and **Run** are not in the sketch; they stay, restyled.
- The sketch's **Problems** tab does not exist yet (Part 7); the Inspector keeps its own content (no big-number summary).
- The banner and bar are not in C's Timeline, Problems and Story sketches; when those parts land, C can hide them there (they live in C's slot).
